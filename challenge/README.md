# Ritoko Challenge

A local, dependency-free successor to rpachallenge.com for testing and demoing Ritoko. One run is N rows (default 10) from a downloadable CSV. Per row:

1. **AI studio** (`/studio`): the row's prompt is generated by a simulated job (20-90 s by default, with progress), then a Download button serves a file with an ugly server name (`gen_8f3a..._final(1).png`).
2. **Entry form** (`/round`): fields shuffled and ids randomized every load, labels without `for`, a select, a checkbox, a date, a phone field inside an iframe, a JS `confirm()` on submit, a random delay with a spinner, and server-side validation. One row has an invalid email: it must end as `review`, never `done`.
3. **Results** (`/results`, paginated, 5 per page) and **score** (`/score`), with a score and timer in every header. `/api/stats` returns what the server really received (`submissions`, `accepted`, `duplicates`, `downloads`...). The server accepts duplicates on purpose: only Ritoko's journal prevents them.

```bash
node challenge/server.mjs [--port 4173] [--rows 10] [--job 20-90] [--latency 300-1500] [--clean]
node bin/ritoko.mjs import examples/ritoko-challenge.json
node bin/ritoko.mjs run ritoko-challenge
```

`--job` is in seconds, `--latency` (submit delay) in milliseconds, `--clean` removes the bad row. `POST /api/reset[?clean]` resets the counters.

The final checks (results extraction, score) run only when every row is done, so with the bad row a run ends `partial` and with `--clean` it ends `done` at 100%.

`examples/ritoko-challenge.json` uses `download.saveAs: "{{item.Slug}}.png"` and `timeoutMs` up to 900000 (AI jobs of up to 90 s). An engine that does not accept them yet needs `120000` and a plain `saveAs`; the e2e test and the media script apply that substitution automatically.

## Films and screenshots

```bash
node scripts/demo/make-challenge-media.mjs <outDir> [--hd] [--job 4-8]
```

Needs Chrome and ffmpeg. It runs the real CLI against throwaway homes and servers and writes `replay.mp4` (full batch, then the same batch again), `crash.mp4` (SIGKILL mid-submission, report, resume, resolve), five PNG stills and `facts.json` with the measured numbers, also covering a broken selector (run pauses with exit code 2, nothing submitted). `<outDir>` should be outside the repository.
